# Fake Claude CLI (tests only)

Stands in for the real `claude` CLI so the chat engine can be tested without spending anything. Put this folder first in `PATH` for a test server:

```powershell
$env:PATH = "$PWD\tools\fakeclaude;" + $env:PATH
$env:MC_PORT = '47903'
node server/index.js
```

- `fake-cli.js`: answers `--version`, and one-shot `-p` runs by echoing the prompt, folder, model, mode and effort.
- Background work: the word `BGAGENT` (a helper agent with `run_in_background`) or `BGBASH` (a background shell command) in a prompt starts a background task that reports itself the way the real CLI's stream-json output does: the tool_result text ("Async agent launched successfully ... agentId: X" / "Command running in background with ID: X"), the `system` events `background_tasks_changed` (the full set of live tasks), `task_started`, and at the end `task_updated`, `task_notification` and `background_tasks_changed` again, then a `<task-notification>` message that the fake answers with a turn of its own, as the real CLI does. It runs `FAKE_BG_MS` ms (default 1500) or `BGMS=<n>` from the prompt. `FAKE_BG_MODE=text` leaves out the system events (only the tool_result text and the notification remain), `FAKE_BG_MODE=lost` never reports the end (to test the safety ceiling). A closed stdin waits for background tasks before the fake exits, like the real CLI. The log gets `bg-start` and `bg-end` lines.
- `fake-cli-live.js`: the stream-json input mode used by Mission Control (one live process per conversation): echoes each message and its block types, simulates a 3-step turn so a second message can join mid-turn, asks for permission when the prompt contains "ASK", and stays alive until stdin closes. It answers the `remote_control` control request (Remote Control, "Show on claude.ai") like the real CLI: success with a fake claude.ai `session_url` by default, or an error when `FAKE_RC` is `error`, `policy`, `silent` or `foreign`. With `FAKE_TRANSCRIPT` set to a folder it also saves its conversation to `<folder>/<session id>.jsonl` as it goes, shaped like the real CLI's transcript (a user record for the first message of a turn, a `queued_command` attachment for a message taken in mid-turn, one assistant record per block), so a test can read a conversation while a turn is still running. A message that arrives while a turn runs is saved at once (a `queued_command` attachment with `source_uuid`), before the turn's result line, like the real CLI; it takes the `uuid` Mission Control gives the message unless `FAKE_UUID=ignore`. `FAKE_END_MS` pauses between the last reply of a turn and its result line (the window in which a late message is queued), and the word `FLOOD` in a prompt streams `FAKE_FLOOD_N` text blocks of `FAKE_FLOOD_B` characters.
